# TaskBoard Pro: Multi-Agent Governance

## 🏗️ The Spec-to-Release Pipeline
This project follows a strict five-phase lifecycle:
1. **Conception** (Spec) -> 2. **Execution** (Orchestrator/Devs) -> 3. **Control** (QA) -> 4. **Release** (DevOps).

## 🤖 Team Mapping
| Role | Skill File | Core Responsibility |
| :--- | :--- | :--- |

| **Agent #00: Specifier**| `skills\00-spec_agent.md` | Functional specs, SSoT, and project milestones|
| **Agent #01: Orchestrator**| `skills\01-orchestrator.md` | API contracts, schema definition, and delegation|
| **Agent #02: Frontend** | `skills\02-frontend.md` | Next.js 15, React 19, Glassmorphism UI |
| **Agent #03: Backend** | `skills\03-backend.md` | FastAPI, Python 3.10+, CRUD & Logic |
| **Agent #04: QA** | `skills\04-qa.md` | Jest/PyTest, Contract & E2E validation and Bug hunting|
| **Agent #05: DevOps** | `skills\05-devops.md` | Repo governance, Docs, Mermaid diagrams, env management and Versioning |

## 📜 Global Protocols
- **Stack:** Next.js 15, Tailwind CSS, dnd-kit, FastAPI (Python).
- **Commits:** Strict Conventional Commits managed by Agent #05.
- **No-Go Zone:** Frontend agents NEVER write backend code; Backend agents NEVER write HTML/CSS.
